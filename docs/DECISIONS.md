# دفتر تصمیم‌ها

ثبت تصمیم‌هایی که پرهزینه‌اند، یعنی برگشتن از آن‌ها گران تمام می‌شود.
هر تصمیم به پرسش‌هایی که موقعی که گرفته شد بی‌پاسخ بودند اشاره می‌کند.

---

## D1 — بدون JavaScript

**تاریخ:** ۱۴۰۵/۰۷/۱۲

**گزینه‌ها:** بدون JS / QuickJS از طریق FFI / V8 از طریق FFI / تصمیم بعدی

**انتخاب:** بدون JS در فاز ۱. JavaScript یک فاز جدا بعد از کامل شدن رندر.

**دلیل.** صادق‌ترین گزینه برای فاز اول. هر صفحهٔ واقعی فرض می‌کند JS هست،
ولی صفحات محتوایی، مستندات، خبری و آرشیو بدون JS هم درست رندر می‌شوند.
همین تصمیم دلیل زنده ماندن `andre-eriksson/browser` است، و تصمیمی است که
بقیهٔ پروژه‌های از-scratch نگرفته‌اند.

**هزینهٔ آگاهانه.** سایت‌های SPA (React/Next/Gatsby) پوستهٔ خالی نشان می‌دهند.
سایت‌های CSS-in-JS مثل styled-components کاملاً شکست می‌خورند، چون CSSشان
را JavaScript در `<style>` تزریق می‌کند.

**بازبینی در:** پایان فاز ۶. اگر آن موقع یک سایت واقعی که برایت مهم است
کار نکرد، این تصمیم باید دوباره باز شود.

**اگر باز شود:** QuickJS حدود ۱ مگابایت و یک موتور ES واقعی است. ولی بعدش
یک لایهٔ binding دامنه (DOM ↔ JS) هم لازم است که خودش کار بزرگی است. یعنی
JS یعنی دو برابر کار، نه کمی. Lightpanda همین را با جاسازی V8 خریده، با یک
snapshot برای startup سریع.

## D2 — ویندوز اول، هسته cross-platform

**تاریخ:** ۱۴۰۵/۰۷/۱۲

**انتخاب:** هستهٔ موتور cross-platform (فقط V خالص)، لایهٔ پنجره جدا.

**دلیل.** `net/http` روی ویندوز از SChannel استفاده می‌کند که بومی است و
dependency ندارد، و Sokol برای GL/D3D11/Metal موجود است. جدا نگه داشتن
هسته از پنجره یعنی cross-platform شدن هزینهٔ کمی دارد، نه بازنویسی.

**ریسک شناخته‌شده.** `vtext` الان Windows-only است — تست‌هایش از
`C:\Windows\Fonts` می‌خوانند. اولین کار برای cross-platform واقعی، درست
کردن همین است.

## D3 — `-cc tcc` برای همه‌چیز

**تاریخ:** ۱۴۰۵/۰۷/۱۲

**دلیل.** این تنها جایی بود که یک ریسک واقعی می‌توانست کل پروژه را متوقف
کند. `vtext` با gcc ساخته می‌شود (به هدر stb_truetype نیاز دارد)، ولی
scoop gcc نمی‌تواند `ws2_32` لینک کند که مسیر SChannel در `net/http`
لازم دارد. قبل از نوشتن موتور باید حل می‌شد، چون همهٔ تصمیم‌های بعدی
(پوسته، loader، تست) ارث این جواب را می‌بردند.

**اندازه‌گیری‌شده، نه حدس.** یک spike بیست‌خطی هر سه را زیر tcc لینک و اجرا
کرد: ۳ فونت بارگذاری شد، glyph رستر شد (۲۱×۲۳ پیکسل)، پاراگراف فارسی RTL
به ۳ خط wrap شد، و `https://example.com/` پاسخ ۲۰۰ داد.

نتیجه: **vweb به MinGW نیاز ندارد اصلاً.** این با `../vtext/env.ps1` فرق
دارد که gcc می‌گذارد؛ آن برای تست‌های خود vtext است.

## D4 — بافر RGBA به‌جای رندر مستقیم به پنجره

**تاریخ:** ۱۴۰۵/۰۷/۱۲

**دلیل.** رندر مستقیم به پنجره یعنی هر تغییر layout یعنی بالا آوردن GPU
context و بصری کردن نتیجه. رندر به بافر یعنی هر تغییر layout یعنی یک فایل
PNG و یک نگاه. برای پروژه‌ای که ۸۰٪ کارش layout است، این تفاوت بین چرخهٔ
توسعهٔ چندثانیه‌ای و چنددقیقه‌ای است.

**هزینه.** یک کپی اضافه هنگام نهایی‌کردن فریم. پذیرفته شد.

## D8 — نام پوشه‌های ماژول V و محل شکست‌های V

**تاریخ:** ۱۴۰۵/۰۷/۱۲

شش شکست پیاپی هنگام نوشتن اولین ماژول، همه از قوانین نحوی V و همه با پیام
خطای **گمراه‌کننده**. گزیده‌ها:

| نوشته شد | پیام واقعی | مشکل |
| --- | --- | --- |
| `Color` استفاده شده، تعریف نشده | `unknown type Color` | واقعاً همین بود |
| `[]u8(len: n)` | `unexpected token ')'` | قالب `len:` **کروشه** است نه پرانتز |
| `mut straight := []u8{len: x}` | `unexpected token ')'` | پیام از خط قبلی بود، نه این خط |
| `row := ...; row += ...` | `` `row` is immutable `` | V 0.5.2 برای هر انتساب نیاز به `mut` دارد |
| `x1 := x + w; x1 > c.width` | `` `x1` is immutable `` | همان |
| `fn (c u8) f()` روی نوع builtin | `unknown function` | متد روی `u8` در V نیست؛ تابع آزاد لازم است |

درس کلی: **وقتی پیام خطای V به خط اشتباه اشاره می‌دهد، خود خط را هم نخوان.**
اولین شکست (`len: n`) پیامش دربارهٔ `n` بود ولی ریشه‌اش نبود؛ ریشه‌اش
`Color` تعریف‌نشده بود که در ۳۰ خط بالاتر قرار داشت. چهار شکست بعدی تا وقتی
همان یکی را درست نکردم، همگی خطای ثانویه بودند.

جزئیات کامل: [`../notes/V-GOTCHAS.md`](../notes/V-GOTCHAS.md)

## D9 — تست‌های golden باید تصویر را بایت به بایت مقایسه کنند

**تاریخ:** ۱۴۰۵/۰۷/۱۲

**دلیل.** این تستی است که خودِ تصمیم‌های D2 و D3 (حساب صحیح) را توجیه
می‌کند. اگر مقایسه با آستانهٔ خطا باشد، رنستر CPU عملاً همان کار را
می‌کند و هزینهٔ D2 بی‌دلیل پرداخت شده.

**پیامد عملی.** یک تست که اولین بارش قرمز است بی‌ارزش است. هر تست golden
جدید باید یک بار روی کد غلط اجرا شود تا مطمئن شویم واقعاً شکست می‌دهد.
